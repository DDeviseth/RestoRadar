RestoRadar

Restaurant database application · Printed blueprint

Application structure

Discover → Directory → Restaurant details → Inspection history
Discover → Search by name / cuisine / borough
Discover → Borough explorer → Filtered directory
Discover → Insights → Aggregate rankings
Manage records → Add / Edit / Confirm delete
Manage records → Inspection records
React + HeroUI + Lucide → HTTP JSON API → Express
Express → MongoDB Atlas, or persistent local development dataset

Data model

Field Meaning
restaurant_id Unique eight-digit identifier
name, cuisine, borough Restaurant identity and search/group fields
address Building, street, ZIP code, retained coordinates
description Editable, derived from recorded fields by default
grades[] Inspection date, grade and score

Database operations

Read: search, filter, paginate and view details. Add: validate and reject duplicate IDs. Edit: preserve ID and inspections. Delete: require confirmation. Group: $group by borough, $sum one per record. Aggregate: $unwind grades, $group by restaurant_id, $sum scores, $match minimum, $sort descending, $limit.

Design

Neighborhood guide: cream, navy, orange, sage and distinct borough colors. Familiar navigation, labeled forms and responsive tables. Inspection scores are not customer ratings.
